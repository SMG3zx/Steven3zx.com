# Public edge ingress options for Janus

Researched on 2026-10-22 for Linear ENG-112 (Edge Proxy and Temporary Domains), under parent spec ENG-79. Facts and sources only, no recommendation; the owner decides. All pages were read on 2026-10-22 through a fetch tool that summarises pages, so wording is the tool's paraphrase, not a verbatim quote. Anything not confirmed on a primary source is marked **unconfirmed**. Prices that come from the earlier note [headscale-derp-hosting.md](headscale-derp-hosting.md) were read on 2026-10-19 and not re-fetched.

## 1. The question and what the edge has to do

- **Flow (ENG-112):** a visitor opens `ab12cd34.steven3zx.com` over HTTPS. The control plane, a Headscale node tagged `tag:ctrl`, maps the Host header to a Deployment, dials the Agent's tailnet address on port 7101 and streams the response back. The ticket asks for origin TLS from a Cloudflare Origin CA certificate with SSL mode Full (strict). Body cap 10 MiB, requests up to 30 s (from the task brief, not re-read in the ticket). Source: Linear ENG-112, read 2026-10-22.
- **ENG-73 decision (comment dated 2026-10-20):** everything runs on the owner's Windows machine in Docker, no VM or cloud host, public edge reached through a Cloudflare Tunnel because "the machine has no public address". It flags that the DERP relay needs public tcp/443 and udp/3478, which a Tunnel does not carry. Source: Linear ENG-73 comment.
- **Facts since ENG-73 (from the task brief, not independently verified here):** today `edge/compose.yaml` publishes Caddy on 80/443 and the owner's public IPv4 is reachable on 443. `edge/Caddyfile` lists fixed hostnames only (www, apex, janus, git, plane), and the `ddns` container keeps proxied A records for www, the apex and janus, plus ssh (DNS only, not proxied). Sources: `edge/Caddyfile`, `edge/compose.yaml`.
- **DERP constraint:** the embedded Headscale DERP needs tcp/443 (shared with the control server) and udp/3478 for STUN, reachable publicly; with a reverse proxy, STUN must still be reachable directly. Headscale's reverse-proxy page lists Cloudflare Proxy and Cloudflare Tunnel in front of Headscale itself as "not supported". Sources: [DERP](https://headscale.net/stable/ref/derp/), [Reverse proxy](https://headscale.net/stable/ref/integration/reverse-proxy/), [headscale-derp-hosting.md](headscale-derp-hosting.md) sections 5 and 6.

Temporary Domains are one label deep (`<8 chars>.steven3zx.com`), which matters for certificates below.

## 5. Option 3: other mainstream choices

### 3a. Small VPS as ingress (Caddy or nginx on the VPS, joined to the tailnet)

The VPS holds the public address and joins Headscale as a node. Either the Edge Proxy itself runs on it (it only needs the tailnet to reach Agents and a lookup path to the control plane) or Caddy on the VPS forwards to the control plane over the tailnet. Cloudflare can stay in front (orange cloud, Origin CA, Full strict exactly as ENG-112 says) or be skipped.

| Criterion | Finding | Source |
|---|---|---|
| TLS | Same choices as option 2 (Origin CA wildcard or DNS-01 wildcard) but on a static public IP. With no Cloudflare in front, only ACME works: Caddy needs DNS-01 for a wildcard. | [Caddy automatic HTTPS](https://caddyserver.com/docs/automatic-https), [Origin CA](https://developers.cloudflare.com/ssl/origin-configuration/origin-ca/) |
| Joining the tailnet | A plain `tailscaled` or tsnet process on the VPS registers against Headscale with a tagged pre-auth key; the ACL would need an explicit rule allowing the VPS tag to reach Agents on 7101 and the control plane. Whether tsnet against Headscale is a tested combination is **unconfirmed** (see headscale-derp-hosting.md section 3). | [headscale-derp-hosting.md](headscale-derp-hosting.md) |
| DERP | Cleanest fit: DERP (embedded in Headscale, or a separate `derper`) can live on the same public host, which satisfies tcp/443 plus udp/3478, a static public IPv4, no NAT. Tailscale says `derper` should not sit behind NAT, a load balancer or another HTTP proxy and shouldn't share an IP with other services if possible. Headscale itself could also move to the VPS, a separate decision. | [Custom DERP](https://tailscale.com/kb/1118/custom-derp-servers), [DERP](https://headscale.net/stable/ref/derp/) |
| Cost | From the earlier note (read 2026-10-19): Hetzner CX23 EUR 5.49/month plus IPv4 (about EUR 0.50, unconfirmed), 20 TB EU outbound; DigitalOcean $6/month for 1 GiB and 1,000 GiB outbound, $0.01/GiB over; Fly.io $3.69 for 512 MB; Oracle Always Free $0 (reclaim risk, capacity errors). | [headscale-derp-hosting.md section 7](headscale-derp-hosting.md) |
| Failure | VPS stays up when the home machine is off, so it can answer visitors with its own 503 page or a custom page; Janus's own design says Agent offline gives 503 anyway (GLOSSARY, Deployment states). No dependence on the home IP, so no DDNS. New failure: the VPS itself, and the tailnet path VPS to control plane (direct or via DERP). Recovery after home outage is as fast as the tailnet reconnect (not documented: **unconfirmed**). | [GLOSSARY.md](../janus-go/GLOSSARY.md) |
| Terms | With Cloudflare orange cloud: CDN restriction applies. With the VPS exposed directly (grey cloud): Cloudflare terms do not apply to the traffic, but the VPS provider's acceptable-use policy does (not read for any provider: **unconfirmed**). | section 2 |
| Operations | A second machine to patch, secure and monitor; one more tailnet node and ACL rule; backups of certs. Most moving parts of the "own-it" options, but each is mainstream. |  |

### 3b. Reverse tunnel to a VPS (WireGuard, SSH, frp, rathole)

Use this only when something at home must be reached from the VPS without the tailnet. Since the control plane is already a tailnet node, a tunnel is redundant for HTTP; it matters for forwarding raw tcp/443 and udp/3478 from a VPS to a home Headscale/DERP.

| Tool | Finding | Source |
|---|---|---|
| frp | TCP, UDP, HTTP and HTTPS; `subdomainHost` plus a wildcard DNS record to the frps server gives `{subdomain}.{host}` routing; TLS on the client-to-server transport on by default since v0.50.0; Apache-2.0. v1 receives only fixes while a non-compatible v2 is under development. How TLS for HTTPS vhosts is terminated and WebSocket support were not stated on the pages read: **unconfirmed**. | [frp README](https://github.com/fatedier/frp), [frp subdomain](https://gofrp.org/en/docs/features/http-https/subdomain/) |
| rathole | TCP and UDP only, transports tcp, tls, noise and websocket, Apache-2.0. No HTTP vhost or SNI routing on the README, so the HTTP routing stays in Caddy at home. Maintenance status not stated: **unconfirmed**. | [rathole README](https://github.com/rathole-org/rathole) |
| WireGuard / SSH reverse forward | Generic building blocks (a UDP VPN, `ssh -R`). Not researched against their own docs here, so no claims about limits: **unconfirmed**. | not fetched |

### 3c. Tailscale Funnel equivalent on Headscale

- **Headscale does not support Funnel.** The features page leaves Funnel and Serve unchecked. Issue #3435 (Funnel request, opened 2026-08-23) is open with labels `not-planned` (added 2026-09-30) and `tailscale-feature-gap`; the maintainer says the main obstacle is infrastructure (Funnel needs public exit nodes integrated with Tailscale's control server and someone to run and police them), and floats an "embedded funnel" in which Headscale itself becomes the public ingress, noting more exposure and load. Issue #1040 (2022) was closed as not planned, with the maintainer saying Funnel depends on a tailnet hosted at tailscale.com. Sources: [features](https://raw.githubusercontent.com/juanfont/headscale/v0.29.5/docs/about/features.md), [#3435](https://github.com/juanfont/headscale/issues/3435), [#1040](https://github.com/juanfont/headscale/issues/1040).
- Even on Tailscale's own control plane, Funnel only serves DNS names under the tailnet's `ts.net` domain on ports 443, 8443 and 10000 with non-configurable bandwidth limits, so it could not serve `*.steven3zx.com`. Source: [Funnel](https://tailscale.com/kb/1223/funnel). **Dropped: unsuitable.**

### 3d. Pangolin (self-hosted)

Open-source WireGuard-based reverse proxy platform; AGPL-3 community edition. Self-hosted install needs a Linux server with a public IP and open tcp 80 and 443 plus udp 51820 and 21820; components Pangolin, Gerbil, Traefik, and Newt connectors at the sites. Wildcard domains are an A record `*.example.com` to the VPS with Traefik requesting certificates; the DNS-01 provider support and behaviour behind the Cloudflare proxy were not stated: **unconfirmed**. It brings its own user, identity and policy layer that overlaps Janus's control plane and a second tunnel mesh next to Headscale. Sources: [Pangolin README](https://github.com/fosrl/pangolin), [quick install](https://docs.pangolin.net/self-host/quick-install), [domains](https://docs.pangolin.net/manage/domains). Not dropped, but the fit is weak because Janus already has its own routing logic (Host to Deployment) and tailnet.

### 3e. ngrok

Free: no custom domains, 1 GB out, 20k requests per month. Hobbyist $10/month: no custom domains, 5 GB then $0.10/GB. Pay-as-you-go $20/month plus usage: custom domains at $0.01 per active hour, wildcard endpoints listed, 5 GB out then $0.10/GB. The pricing page has no visible date (**treat as unconfirmed for today**). Source: [ngrok pricing](https://ngrok.com/pricing), read 2026-10-22. **Dropped: unsuitable** because per-GB and per-request pricing and the domain model do not suit serving many user sites under the owner's own domain, and it would not carry DERP.

## 6. Option 4: Cloudflare Workers and Workers VPC

A Worker on `*.steven3zx.com` receives the request and reaches a private origin through a Workers VPC binding that rides a Cloudflare Tunnel.

- Workers VPC is "currently in beta", free for all Workers plans during the beta, supports HTTP and TCP, and uses `cloudflared`; pricing after beta and usage limits are not stated. Whether a custom Host header can be set on VPC fetches is not stated: **unconfirmed**. Source: [Workers VPC](https://developers.cloudflare.com/workers-vpc/).
- Workers Free: 100,000 requests per day (Error 1027 when exceeded), 10 ms CPU per request, 50 subrequests, request body per account plan (100 MB on Free), no hard wall-time limit while the client stays connected. Paid: $5/month minimum with 10 million requests included, $0.30 per additional million; CPU time default 30 s, up to 5 min. Sources: [Workers limits](https://developers.cloudflare.com/workers/platform/limits/), [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/).
- It still needs a Tunnel on the home machine, so offline behaviour, ToS and DERP are those of option 1; a Worker would let Cloudflare answer when home is offline (own inference). It moves the Host-to-Deployment lookup out of the control plane unless the Worker calls back to it, which does not match ENG-112 as written. **Judged a poor fit**, kept for completeness.

## 7. Option 5: Cloudflare Spectrum

Spectrum proxies TCP and UDP applications, supports UDP and TLS termination for TCP applications, and is listed as available on paid plans, with custom TCP/UDP applications requiring Enterprise as a paid add-on. Pricing is not public on the pages I read: **unconfirmed**. It could in principle carry udp/3478 and tcp/443 for DERP while hiding the home IP, but nothing I read confirms that on a non-Enterprise plan, and it is not needed for HTTP because the normal proxy already serves that. Sources: [Spectrum](https://developers.cloudflare.com/spectrum/), [configuration options](https://developers.cloudflare.com/spectrum/reference/configuration-options/). **Dropped: unsuitable for a solo developer on Cloudflare Free**; revisit only if DERP must hide the IP.

## 8. Option 6: Cloudflare for SaaS

Custom Hostnames for customers' own domains: 100 hostnames included on Free, Pro and Business, up to 50,000, $0.10 per extra hostname. Source: [Plans](https://developers.cloudflare.com/cloudflare-for-platforms/cloudflare-for-saas/plans/). **Dropped for M1:** Temporary Domains are subdomains of the owner's own zone, so Universal SSL and one wildcard record already cover them. It becomes relevant only if users later bring their own domains (out of scope here; fallback-origin requirement not confirmed).

## 10. What would decide it

- **Is DERP at home or on a VPS?** Only a public host (router forwards or a VPS) can carry DERP. If the owner will not forward udp/3478 at home, a VPS is needed for DERP in every option, and then option 3a costs little more than its DERP role already does.
- **Can the router forward udp/3478 and a second tcp/443 use?** Today 443 goes to Caddy; DERP and Headscale also want 443. Without a second public IP or SNI routing, this collides.
- **How bad is "Cloudflare is the only way in"?** Tunnel and Spectrum put the single Cloudflare account in the data path; option 2 and a direct VPS keep a path that works without Cloudflare.
- **Does the owner want the home IP hidden?** Tunnel hides it for HTTP; a grey-cloud DERP name exposes it under option 2.
- **Does the ENG-112 acceptance wording matter?** "Origin CA with Full (strict)" fits options 2 and 3a, and has no documented meaning for option 1 unless the Tunnel's local service is HTTPS. The wording may need to change if Tunnel stays.
- **Expected content mix.** If users will serve video or large downloads, the CDN terms apply to every Cloudflare-fronted option; the only way out of Cloudflare's CDN rules is a direct VPS (grey cloud).
- **Is "up only while the machine is on" acceptable?** Options 1 and 2 serve nothing when home is down (1033 or 521 pages); 3a can serve a custom page.
- **Tolerance for another host to run.** 3a adds one VPS to patch; options 1 and 2 add none.
