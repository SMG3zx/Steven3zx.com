Version 0.3 focus

Version 0.3 turns broad system fields into explicit subfields so each boundary can be implemented, tested, traced, and reviewed independently.

Domain fields

  • Identity: tenant, subject, entity, command, generation, and tick.
  • Lifecycle: admission, state, transition, failure, retry, and completion.
  • Authorization: principal, permission, tenant match, capability, and expiration.
  • Durability: reducer, version, journal event, snapshot, receipt, and recovery job.

Evidence fields

  • Verification: test target, assertion, severity, count, remediation, and exit condition.
  • Trace: profile, process/thread track, span, timing, status, and arguments.
  • HTTP: route, method, authentication policy, request shape, response envelope, and status.
  • Operations: owner, boundary, input, output, failure policy, and capacity limit.

Version 0.3 rule: a field is not complete until its subfields have an owner, a bounded representation, a Rust test, and live evidence in the specification where applicable.

2. Architectural model

Janus remains an actor-owned Entity Component System. Each actor owns a bounded World. Commands enter through admission checks, systems mutate components, and effects leave the world only through explicit records.

2.1 Entity identity

  • EntityId identifies builds, deployments, and future operation entities.
  • TenantId is carried through every tenant-owned command and component.
  • CommandId provides idempotency for command admission.
  • Generation fences stale worker and runtime callbacks.
  • Tick provides deterministic simulation time.

3. State and transition rules

3.1 Build lifecycle

Pending → Running → Succeeded or Failed. A non-terminal build may be cancelled. Completion is accepted only from the current worker generation.

3.2 Deployment lifecycle

Pending → Starting → Running. Runtime failure produces Failed; intentional shutdown produces Stopped. Runtime callbacks are generation-fenced.

3.3 Operation lifecycle

Pending → Processing → Succeeded or Failed. Terminal states cannot transition again. Operations are stored in bounded ECS slots and included in snapshots. The status rank must never decrease:

pending = 0
processing = 1
succeeded | failed | dead_lettered | expired = 2

4. Security and ownership

  • Every tenant-owned command is authorized before it reaches the mailbox.
  • Tenant mismatch is rejected before state mutation.
  • Permissions are explicit: build submission, build cancellation, deployment management, build reads, and control-plane operation.
  • Resource release requires the owning entity and generation.
  • HTTP routes distinguish public, authenticated, and permission-protected behavior; bearer sessions are converted into tenant-scoped principals before dispatch.

Password verification is an explicit PasswordVerifier adapter boundary. The ECS does not embed a placeholder hash algorithm; a production credential adapter must provide the approved password-hash implementation. FileAuthStore persists bounded users, permissions, sessions, tenant links, expiration, and MFA state; the Actix configuration adapter supplies its MFA encryption secret and fails closed when JANUS_AUTH_FILE is configured without a production secret.

5. HTTP compatibility contract

The Rust route table contains the 57-route Go/Zig compatibility surface. It records stable paths, prefix behavior, methods, handler identity, authentication policy, and route group. Actix Web is the production HTTP framework; the framework-independent HttpService remains the deterministic contract layer.

Implemented boundary behavior includes:

  • /healthz, /readyz, and /metrics.
  • Bounded HTTP request parsing with a 16 KiB request limit.
  • Query-string stripping before route matching.
  • Authentication-required responses for protected routes, with bearer-token parsing, session-to-principal permission propagation, authenticated dispatch, and typed Actix project handlers.
  • The Actix default dispatcher now carries a valid bearer session’s tenant-scoped principal into the compatibility layer, so protected non-project routes receive the same authorization behavior as the framework-independent service.
  • Public operation lookup fallback behavior.
  • Operation lookup now matches the Go missing-resource response: HTTP 404 with {"error":"operation not found"}.
  • Template and backend-resource routes preserve the Go response shapes behind the existing authentication policy.
  • Telemetry, billing, logs, events, admin, and telemetry-view response shapes are implemented in the deterministic HTTP contract; method-sensitive telemetry views preserve GET versus POST status behavior.
  • API and frontend fallback handling.
  • A Rust test parses the Go router registrations, including both mux.HandleFunc and mux.Handle, and fails if any of the 57 route paths or normalized handler identities diverge.

6. Local verification system

antithesis-local executes deterministic Rust scenarios and writes one JSON object per line. Each event contains the assertion condition, source location, lifecycle details, stable message, and hit state.

rustup run stable-x86_64-pc-windows-msvc cargo run \
  --manifest-path janus-rust/Cargo.toml \
  --bin antithesis-local -- \
  --output janus-rust/artifacts/rust-assertion-events.jsonl

The runner checks command admission, build progression, operation monotonicity, world invariants, duplicate-effect idempotency, dropped-effect recoverability, deployment runtime identity, and replay transcript equality. A failed assertion is recorded and causes a non-zero process failure. antithesis-validate validates the JSONL schema and failure state, while antithesis-diff compares Go reference events; lifecycle statuses and endpoints remain exact while opaque runtime IDs are compared by presence.

8. Persistence and replay

  • Events are ordered and versioned; the Rust ECS snapshot protocol is now version 5 because builds persist project and source-reference metadata and deployments persist project ownership, explicit temporary-domain revisions, target and runner metadata, bounded environment entries, and runner runtime metadata, and older snapshots fail closed as unsupported.
  • FileEventJournal provides bounded append-only recovery with corruption and sequence validation.
  • Snapshots preserve world state and command idempotency.
  • Replay regenerates the same deterministic transcript.
  • Dropped and duplicated effects are modeled and tested.
  • SpacetimeDB is the production persistence authority: every bounded control-plane record must be represented by tables, indexes, and reducers, and Actix must hydrate and mutate through the generated client.
  • The authenticated telemetry endpoint now serves durable tenant-scoped metrics, trace spans, searchable logs, and profile indexes from the generated SpacetimeDB materialized tables; only large bodies remain in external object storage.
  • Source and artifact uploads now write tenant-scoped object metadata and artifact metadata through generated reducers, with retention reducers and failure cleanup for both durable projections.
  • Local file journals and queue stores remain deterministic fallback adapters for offline development and replay.
  • janus-spacetimedb contains the deployable Rust module boundary; janus-core contains the database-independent contract and local reducer implementation. Auth sessions are modeled as durable rows with tenant, expiry, MFA, and revocation state, while normalized identity and authorization tables remain part of the migration work.

9. Capacity and failure policy

  • Mailboxes, worlds, resources, trace samples, and simulation steps are bounded.
  • JobQueue provides idempotent enqueue, worker leases, retry limits, dead-letter states, and validated FileQueueStore recovery.
  • ObjectStore adapters validate keys and enforce per-object and total byte limits.
  • EmailOutbox provides idempotent delivery intent, provider claims, retries, terminal failures, and an explicit EmailTransport delivery port; SMTP remains the concrete transport adapter.
  • RunnerRegistry enforces tenant ownership, capabilities, heartbeat leases, busy/released state, and offline expiration.
  • RuntimeRegistry enforces artifact-key safety, filesystem/process capability policy, tenant ownership, and generation-fenced lifecycle callbacks.
  • TelemetryBuffer validates bounded metric names/labels and finite values before exporter delivery; PrometheusTextExporter renders bounded samples with escaped labels and timestamps. The Actix adapter now serves live /healthz, readiness-aware /readyz, and real buffered Prometheus /metrics output rather than static compatibility envelopes.
  • Zero capacities and missing capabilities are configuration errors.
  • Invalid transitions are classified rather than silently ignored.
  • Unsafe Rust is forbidden.
  • Clippy warnings are treated as errors for verification.
