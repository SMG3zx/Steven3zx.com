# Structure janus-go as ports and adapters, with no actor framework

janus-go is built as a core of domain rules and use cases that imports no I/O, with every outside effect behind a port the core declares and adapters wired together in `cmd/janus`. We chose this because the GoAkt usage audit written for ENG-61 (`docs/goakt.md` when it was written) shows Janus uses only `Tell`/`Ask` and one `PipeTo` of GoAkt's features, while the actor layer costs about 100 type-asserted `Ask` calls and breaks the framework's own rule against blocking in `Receive`; because the measurements in `experiments/store-concurrency` show an actor is not faster than a lock (a sharded mutex is about six times faster in memory, and every single-owner design ties at the speed of one database connection, which is where the store lives); and because ports with in-memory test adapters let the core be tested without Docker, GitHub or a database file. The cost is that shared state now needs correct locking, checked with the race detector, and that GoAkt's clustering is no longer an option if the control plane ever needs more than one node (ENG-56), which would then be solved at an adapter. The decision relaxes the testing rule in ENG-79: fast tests may use test adapters, and live tests still cover every real adapter. Dropping GoAkt was approved on 2026-10-20. It is reversible module by module until GoAkt is removed from `go.mod`, so the migration in `docs/architecture.md` ships in steps. The standard is in `docs/architecture.md`.

GoAkt was removed from `go.mod` in ENG-71 on 2026-10-20. The store-concurrency experiment moved into its own module so it can still be rerun.
