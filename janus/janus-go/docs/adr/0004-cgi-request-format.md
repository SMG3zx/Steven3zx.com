# A Deployment's module speaks CGI/1.1

ADR 0002 has the Agent start a module for each request, passing the request in through the environment and stdin and reading the response from stdout. This ADR fixes the format: CGI/1.1 (RFC 3875), as WAGI uses it. The request arrives in the CGI variables (`REQUEST_METHOD`, `PATH_INFO`, `QUERY_STRING`, `CONTENT_TYPE`, `CONTENT_LENGTH`, `SERVER_NAME`, `REMOTE_ADDR`, one `HTTP_<NAME>` per request header, and the rest), with the body on stdin. The module writes header lines to stdout, then a blank line, then the body. A `Status` header sets the status, a `Location` header without one means 302, and otherwise the status is 200. Output with no blank line, or with a header line that is not `Name: value`, is not a response, and the edge gets a 502. The translation lives in `internal/domain/cgi`.

We chose an existing convention so that users can follow its documentation and reuse CGI libraries in any language that compiles to WASI, instead of learning a Janus-only format. The cost is CGI's limits: the whole request and response are buffered (capped at 10 MiB each), there is no streaming, and headers are flattened into environment variables. Users write their code against this format, so changing it later would break every Deployment. Decided in ENG-111.
