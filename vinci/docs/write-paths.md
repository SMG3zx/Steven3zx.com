# Write paths

Every path that writes the journal, the index or a file under `$VINCI_HOME`, the chat's tools, the tracker and the feeds included. For each: what triggers it, whether its input can come from untrusted text, what gates it, and the test that covers it. The rule the gates follow is in [mark 3, section 2.6](mark3-plan.md#26-security-the-rule-of-two-per-surface): once untrusted text is in a chat's context, a write needs the person's yes.

Gate terms: **none** (runs without asking); **y/N** (the chat asks once a write is requested after untrusted text entered the conversation; anything but y or yes is no, and end of input is no); **human only** (a command the person types, with no model between).

The journal command classes are in one table, `py/vinci_core/command_kinds.py`. A unit test (`py/tests/test_command_kinds.py`) fails when a command the dispatch sources compare with is missing from it, or the table names one they do not.

## The read tool's boundary (changed in K0b)

Before K0b, `read` accepted any `.md` or `.txt` on disk and any `http` or `https` address, including loopback services such as the model server and the portal. Now (`py/vinci_edge/read_guard.py`):

- **Files** must be under the account's home folder (from the password database, not `$HOME`), with `..` and symbolic links resolved first, and not under `~/.ssh`, `~/.gnupg`, `~/.aws`, `~/.config`, `~/.local/share/keyrings`, `~/.claude`, or `$VINCI_HOME/backups`.
- **Web addresses** must be `http` or `https`. Every address the name resolves to must be public: loopback, link-local, private (RFC 1918 and unique-local), unspecified, multicast and non-global addresses are refused, and an IPv4-mapped IPv6 address is judged by its IPv4 part.
- The connection is made to the address that was checked, so a name that changes its answer after the check cannot reach a private address. Every redirect hop is checked the same way, and a `file:` or `ftp:` hop has no handler. No proxy from the environment is used.

## What the audit found

Cross-checked against the code, in K0b:

1. **The tracker wrote without a gate from the chat.** A read-only chat command such as `ideas` ran `vinci journal ideas` with the tracker on, and the tracker writes `spent`, `work` and `used` lines from window titles and commit subjects. Changed: a read-only command from the chat runs with `VINCI_NO_TRACK=1`. The totals a chat answer shows can lag by one sync until the next CLI command or a write.
2. **The chat's fence was a hand-written list, and `feed` was not on it.** `journal feed` ran from the chat, and `backup` and `verify` did not exist. Changed: the fence is the table. `feed`, `backup` and `verify` are now refused by the chat, along with the words the old list refused. Refusal text is unchanged.
3. **The `read` tool could read loopback services and any text file on disk.** Changed: see the boundary above.
4. **Two writers could mint the same id.** `next_id` read the journal, then appended, with no lock. Changed: every read-then-append runs in one `JournalTx` under an exclusive `flock` on `journal.jsonl.lock`. In the race test (four writer processes, 400 `idea` lines, two reader processes running `ideas` and `stats` throughout) the locked binary had no duplicate id and no reader failure in any run. With the lock switched off (a test-only switch) there were 56 to 100 duplicate ids. The HEAD binary had 85 to 105. (An earlier build, whose readers took no lock and did not skip a half-written last line, failed a read with `json: line ended early`; the readers now skip it.)
5. **A failed command could leave some of its lines behind.** Each `record` appended at once. Changed: a command's lines are written at the end, with one fsync, or not at all when it fails. The tracker's lines are still written before the command, as before.

Not changed, and why:

- **The exchange lines are written without a gate.** They are the chat's own log of a turn, not a tool call. The index marks assistant lines untrusted, so they cannot pass as the person's writing. Gating them would stop a turn from being logged at all.
- **Index lag.** `vinci verify --index` on the real journal found the stored index one `work` line behind the journal. Which commands leave it behind: every CLI command that writes a journal line (the writers in the table, and the tracker lines any CLI command can write), because none of them updates the index. Only `vinci index update` or `rebuild`, `vinci feed run journal`, and the chat after its own writes (and when it starts) update it. Left as it is; the fix is for the brief.
- **Reads create nothing.** A read-only command, `verify`, the portal and the index update never create `$VINCI_HOME` or the lock file, and never wait for a writer (checked: `ideas`, `stats`, `pipeline` and `path` on a missing home; `ideas` on a home with nothing due). Two exceptions, both writes: a command that writes, and a tracker sync that has facts to write. The portal still creates `previews/` when it starts (`portal.mojo`, not changed in K0b), which creates `$VINCI_HOME` if it is missing.
